шпаргалка по гиту 
git restore - нужен,когда я случайно изменила файл и хочу его вернуть в первоначальное состояние 
git checkout нужен когда я хочу посмотреть определенную ветку,коммиты или другие версии проекта и переключаться между ними 
HEAD detached это когда я нахожусь на конкретном коммите а не на ветке и могу посмотреть старую версию проекта 
git revert нужен для того что бы отменить изменения коммита но при этом старый коммит остается в истории 
git switch -c нужен для создания новой ветки и сразу переключиться на нее
fast -forward это когда гит объеденяет ветки без нового коммита слияния потому что основная ветка не менялась 

конфликт слияния в гит это когда в двух ветках по разному изменили одну и ту же часть файла и гит не знает какой вариант выбрать.
Нужно выбрать правильный вариант убрать обозначение конфликта сохранить файл.
после исправления конфликта нужно выполнить гит адд и гит коммит что бы завершить слияние.

Шпаргалка урок 4
1.Merge Request (Pull Request)-это запрос на объеденение своей ветки с главной веткой main.
2.Reviev-эта проверка работы напарника.мы оставляли комментарии,задавали вопросы,предлагали улучшения и одобряли изменения.
3.Я создала ветку add-food и добавила фаил food.txt где можно поесть в Астане 
4.Затем я изменила README.md,сделала git add,git commit и git push,чтобы отправить работу на GitHub 
5.Я создала Pull Request, а напарница проверила мою работу и попрасила добавить адреса заведений.
6.Я исправила замечание,сделала новый коммит и отправила изменния.После Approve объединила свою ветку с main.
7.Я также проверила Pull Request напарницы add-walks,оставила три комментария:вопрос,предложение и похвалу.
8.Конфликт слияния возникает,когда два человека по-разному изменяют одну и ту же часть файла, и Git не знает, какой вариант выбрать.
Чтобы решить конфликт,нужно открыть файл, выбрать правильный вариант,удалить маркеры конфликта и сохранить изменения.Затем выполнить git add и git commit, что бы завершить слияние.
9. По домашнему заданию конфликт должен был возникнуть в README.md, потому что мы обе изменяли первую строку.
10. Для решения конфликта участник напарница  должен перейти в свою ветку командой git switch add-walks,
 выполнить git merge main, открыть README.md и удалить маркеры конфликта.
11. После исправления нужно выполнить git add README.md, git commit и git push, чтобы сохранить и отправить изменения.
12. После объединения веток я перешла в main с помощью git switch main и выполнила git pull.
13. Команда git branch показывает ветки, а git branch -d удаляет локальную ветку после объединения.
14. Команда git status показывает состояние файлов, а ls — содержимое папки проекта.
